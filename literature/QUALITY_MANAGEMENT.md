# World Models for Physical AI：质量管理规则

版本：v1.0；制定日期：2026-10-03（北京时间）。

状态：**规则已制定，待负责人确认；三个执行阶段尚未启动。**

本轮授权仅限制定规则。规则完成后暂停目标，等待用户下一步指令；不得提前清洗数据、补充论文、修改正文、批量部署工具或给同学派发任务。已有论文、目录和核验记录保留原状，本文件不追认其全部合格。

## 1. 目标、范围与原则

目标是形成来源可靠、分类一致、论证有依据、可以交叉复核的 ACM Computing Surveys 综述，而不是用文献数量替代质量。

正文维持四部分：基础与发展脉络；数据、表示与模型；机器人策略融合；评估、可靠性与前沿。七个主题维持为检索视图，不再扩展成无依据的十几章。

采用现有的 structured narrative review + critical evidence map。除非补齐相应流程并经负责人同意，不改称 comprehensive systematic review，不声明“首个”“最全面”或穷尽召回。

2000–3000 篇是候选发现池的规模规划，不是最低引用量或全文精读量。报告必须分别列出原始检索记录、去重候选、纳入论文、全文提取记录、正文引用；不得把这些数量互换。

质量检查有四条独立轴：身份真实性、纳入适配性、证据可追踪性、结论适当性。正式发表、引用量高、仓库收录或代码开源，均不能单独证明结论正确。

## 4. 纳入角色与适用边界

角色与审核状态分别填写，不能用“已发表”代替“已核验”，也不能用“待核验”代替一篇工作的研究角色。

| 角色 | 纳入条件 | 不能据此做的判断 |
|---|---|---|
| 核心预测/世界模型方法 | 原文可定位环境演化、未来观测、latent、结构化状态或后果预测；与本综述的物理建模问题直接相关 | 被动预测不自动成为动作条件模型；没有控制实验不自动证明控制收益 |
| 支撑资源/理论 | 数据、仿真器、表示、控制理论、指标或综述，且能说明训练条件、接口、概念或评估方法 | 数据集、静态编码器、传统物理引擎或观点文不因有用就成为学习世界模型 |
| 边界对照 | 非世界模型方法，用于比较直接策略、规划、安全、监测、求助或恢复接口 | 不计入世界模型方法数；不把其效果归因于世界模型 |
| 暂缓/排除 | 身份不明、无法获取足够原文、主题不相关、重复出版版本或仅有二手能力描述 | 不进入已核验正文证据；暂缓不等于论文质量低 |

核心方法仍须标注用途：被动预测/表征、动作条件预测、目标条件生成、联合世界与动作建模等。训练时预测和部署时预测必须分开；有 future head 不等于部署时进行在线 rollout。

理论、综述、benchmark、数据与工业技术报告可以纳入其适用角色，不统一要求实体机器人实验。工业报告只能支撑明确披露的内容，不能代替独立验证。

排除或暂缓至少写一个明确理由：重复版本、超出范围、身份无法确认、只有二手来源、全文不可得、证据不足以支持拟写判断。全文不可得不作为否认论文存在的依据。

## 5. 身份、版本、去重与真实性

1. 到作者原文、正式出版社/会议页或官方 arXiv 页面核对标题、作者、年份、来源与标识符。项目页和综述仓库优先用于发现，不独立证明实验结论。
2. 对接纳状态分开记录：正式会议、正式期刊、官方已接收但未出版、workshop、预印本、技术报告、未确认。主会与 workshop 不混用。
3. 分开保存首发日期、正式出版年份和所用版本。不能用 arXiv 编号猜正式发表年份，也不能凭 BibTeX key 的年份判错。
4. 使用完整作者元数据；展示页可以 et al.，不得将缩写展示误当原始作者列表。机构或团队作为作者须有原文依据。
5. 去重优先使用 DOI、arXiv ID、规范题名与作者核对。近似题名只产生人工检查候选，不能仅按相似度自动合并。
6. 预印本与正式版归入同一论文族，保留版本关系；若内容或实验改变，证据绑定具体版本。相同实验被扩展稿复用，不当成独立重复验证。
7. 发现同一链接对应不同题名、同一题名对应不同标识符、错误作者或假冒正式状态时，暂停受影响记录的使用并复核原始来源。
8. DOI 不存在、来源无 DOI 或正式全文不可公开访问时，保留真实状态与可核身份入口，不伪造 DOI，也不把暂时无法访问直接判为伪造论文。
9. 不公开校园代理、临时签名链接、访问 token 或私有路径；正文可公开入口与内部全文访问方式分开。

“身份真实”不等于“实验已复现”。本项目审核原文真实性与主张对应关系，不声称自行重现实验。

## 6. 审核状态与最小填写项

不使用统一 A/B/C 证据等级。采用可观察的工作状态，并注明审核范围。

| 状态 | 升级条件 |
|---|---|
| 候选发现 | 记录原始检索入口；尚未确认身份与相关性 |
| 身份已核 | 题名、作者、版本、出版状态与原始入口已核；不代表读完方法或实验 |
| 范围已审 | 有角色、主主题和纳入/排除理由 |
| 证据已提取 | 对拟支持的判断完成适用的原文提取，附位置和限制；不声称全文所有主张均核验 |
| 判断已复核 | 第二位复核者检查所用原文位置与正文表述；没有第二位时注明“仅单人核验” |
| 暂缓/排除 | 有具体原因、影响范围与后续处理条件 |

已有批次不能仅凭文件存在自动升为“判断已复核”。复核人未实际检查，不登记其名字或独立复核状态。

同学常用表建议保持八个展示栏：论文标题；作者/年份/来源；规范链接与版本；主题与角色；预测—动作—用途；主要证据与结论；局限/待核验；审核状态。

这是展示安排，不要求本轮改 Excel。底层仍分开保存作者、年份、venue、状态、标识符、原记录编号、提取人、复核人、审核日期和引用 key；审核备注不全部塞进可见表头。

空值使用明确含义：未报告、尚未核对、不适用、来源不可访问。不能把“未报告”填成“否”，也不能自动补摘要、实验数字或推断作者未做过某项测试。

## 7. 七类文献的专项检查

| 主题 | 必须问的问题 | 典型越界 |
|---|---|---|
| 世界模型基础与控制 | 模型假设、状态/观测、学习或规划方式是什么；理论保证依赖什么条件 | 把理论假设下的保证写成任意真实环境安全；把所有 RL 都列为世界模型 |
| 视觉与视频世界模型 | 条件是动作、目标、文本还是历史；单段生成还是可交互滚动；评价视觉还是功能 | 视频好看就证明物理正确、可控或真实机器人可用 |
| Latent 与预测表示 | 预测目标和损失是什么；动作是否进入；预测是在预训练、策略训练还是部署阶段 | 静态编码器或预测预训练表示自动变成在线规划器 |
| 结构化物理与多模态 | 几何、接触、力或触觉预测什么；同步、物理量校准与控制接口如何连接 | 视觉 poke 等于校准力；几何可视化等于可执行控制；加传感器的收益全归预测 |
| 数据、模拟与跨本体 | 数据来源、动作坐标、许可、训练测试拆分、平台与适配预算是什么 | 数据规模等于能力；同一机器人换场景等于跨本体；模拟器本身等于学习模型 |
| 世界模型与 VLA、规划 | 未来用于生成、评分、训练还是检查动作；部署是否查询预测；是否有匹配消融 | 总系统增益直接归因预测器；推理器编辑动作等于显式未来预测 |
| 评估、安全与 Benchmark | 评测对象、协议、指标、分母、风险定义与响应接口是什么；有何保证条件 | 离线报警等于事故减少；零事故小样本等于保证；不同 benchmark 数字混排 |

三位同学的分工建议：A 负责基础/控制与 latent；B 负责视觉、物理多模态与数据；C 负责策略规划与评估安全。该安排待负责人确认；不按 sheet 数平均考核，C 的核验负担需单独控制。

## 8. 原文证据提取规则

### 8.1 方法与实验论文

主要证据按三个层次写：实验观察；作者结论；可支撑的综述判断。建议格式：

> 在【环境/数据】中，方法由【输入】预测【目标】，用于【训练/规划/控制/模拟/监测】；相对【对照】，在【任务/指标】观察到【结果】。作者解释为【结论】。本综述据此仅支持【带范围的判断】。位置：【版本、章节、图/表/页】。

数字同时记录指标单位、任务、平台、试验/seed 分母、比较对象及来源位置。百分点与相对百分比、任务均值与 pooled rate、policy 数与 episode 数、不同版本结果不得混用。

原文没有数字就不造数字；没有匹配消融就不归因单一组件；未报告方差就不称统计显著；从别文引用的基线标为引用结果，不写成作者同设置重跑。

局限分开写：作者明确说明；我们从协议识别的推断边界；尚未核对的项目。缺实体验证只限制实体应用判断，不否定仿真、理论或表示学习贡献。

### 8.2 其他研究类型

| 类型 | 应提取什么 | 不强制填写什么 |
|---|---|---|
| 理论/算法保证 | 定义、假设、定理、保证范围与证明位置；实验另记 | 没有实验时不编任务、试验次数或实体结果 |
| 数据集/仿真资源 | 采集与生成方式、规模单位、平台、标注、拆分、许可、局限 | 不要求资源本身提供世界模型控制消融 |
| Benchmark/指标 | 测什么、怎么测、拆分与泄漏风险、指标含义、校准/调参方式 | 不把检测分数等同安全干预效果 |
| 综述/观点/报告 | 定义、分类、披露内容及主张来源 | 不把综述转述作为原始效果证据，不为无实验观点填写成功率 |

原始结论存在冲突或负结果时保留，不只选能支持当前故事的论文。对可比性不足的结果做机制比较，不做无条件横向排名。

## 9. 补漏、覆盖与停止规则

基础文献不限于 2026 年；近期层覆盖 2026 年截至执行批次的明确截止日。每次检索登记实际日期，不在规则中把未来论文预设为已存在。

每个重要方向检查历史基础、当前代表机制、替代/反例、数据与评价条件。没有适用的某一类时写理由，不为凑格子硬找三篇。

补漏渠道为：原始会议/期刊检索、关键词、种子论文后向参考文献、可访问的前向引用索引、作者/团队、数据/benchmark 沿革与 GitHub 近邻。GitHub 是发现渠道之一，不代替原始来源核验。

检索日志最少保留：日期、覆盖问题、渠道、精确 query/种子、过滤条件、实际返回量（未记录填 NR）、去重候选量、纳入/暂缓理由与残余缺口。无法访问前向引文渠道要写明，不用“Google 搜过”冒充全量引文追踪。

七类覆盖表最小字段：主题/问题、已有锚点、历史与近期机制、后向检查、前向检查、会议/团队检查、反例、未解决缺口、负责人、结论依据。

覆盖状态区分：未检索、仅有线索、原文已核、当前稿已覆盖、证据仍不足、界外。不用“论文多”自动判覆盖充分。

停止扩展某问题的条件是：种子是否追回、计划渠道是否实际执行、是否遗漏关键机制、近期增量是否仍改变论证、残余风险是否已说明。停止依据须记在日志中；连续若干次没找到或已达到数量目标不独立证明全面性。

冻结后新论文作为增补：查重、记录加入原因、复核版本、说明是否改变判断。遇到重大漏项，修检索策略，不只补一条然后宣布完成。

## 10. 综合写作与图表规则

每个小节以一个比较问题组织，而不是按作者逐篇排队。建议顺序：问题与机制；不同方案的接口差异；可比证据；综合判断及开放问题。必要的代表案例可以逐篇说明，不机械删除案例段落。

比较至少说明预测对象、动作关系、训练/部署用途和评价设置。将“相同的模型名称”与“相同的系统用途”分开，将“相同 benchmark 名称”与“相同实验协议”分开。

主要综合判断必须关联原始来源、适用范围和反例检查。单篇只能支持该篇条件下的观察；跨篇共识须说明一致性、异质性与证据依赖，不能按论文数量投票。

拟写关键判断须回答：有哪些原文直接支持；比较是否匹配；是否可能由额外数据、模型规模、传感器、预算或人工干预解释；是否有反例；表述是否超出实验范围。未排除替代解释时降为关联或系统级判断，不要求我们替原作者做新实验。

未来方向须区分“当前检索尚未找到证据”与“作者明确证明的限制”。“尚未发现”必须附搜索范围，不能直接写“领域不存在”。

图表采用本项目数据重新设计，借鉴组织方法不复制别人的数据、图片或无依据的勾叉。对每个图表元素说明其语义；数据、性能排名与概念示意分开。复用图片先核许可证与署名要求。

图表验收检查：标签与正文术语一致；字体可读；无遮挡、截断或失控换行；图注解释边界；表格数字与原文对应；不因压缩版面删掉分母或关键限制。优先打磨现有 2 图、8 表，不以新增图表数量作为进度。

## 11. 三阶段门禁与交付

“第 1/2/3 周”是工作顺序，不是自动按日历升级。可按批次推进三个任务，但一条记录未通过前置门禁，不能跳到已复核正文证据。

| 门禁 | 必须交付 | 通过条件 | 不通过时 |
|---|---|---|---|
| G0：规则与范围确认 | 本规则、角色/字段/边界说明 | 负责人明确确认当前版本与首批范围 | 等待指令，不执行三个阶段 |
| G1：统一口径、清洗存量 | 统一主表、身份/版本修正、合并/不合并与排除理由、正文引用身份核查 | 全部当前正文引用完成身份与版本核对；全量候选有可追踪来源和明确状态；无未处置错链或冲突被当成已核验；各层计数可复算 | 候选可留待核验；受影响正文引用修复、暂撤或标为阻断，不假装核完 |
| G2：围绕缺口补漏 | 七类覆盖表、实际检索日志、有理由的新候选与证据提取 | 七类均有覆盖结论和依据；关键缺口完成计划渠道或明确披露渠道限制；新增记录查重并核身份；会改变正文判断的工作回原文 | 保留证据不足状态；收窄所支持判断，不以收集数量验收 |
| G3：由逐篇介绍转为综合 | 四部分第二稿、机制比较表、更新后的主张溯源、编译 PDF | 各节形成比较问题与综合回答；关键判断、数字和图表事实全部定位原始证据并交叉复核；无未定义引用、引用缺项或未处置版面溢出；无跨协议无条件排名 | 退回具体小节/判断，不为排版通过就判学术质量通过 |

G1 的“全部”是执行批次冻结时实际正文引用集合，不永久固定为 117。候选池允许未核记录存在，但不能将其统计成已核验纳入论文。

G2 可以在有渠道限制的情况下通过“有边界综述”门禁，前提是明示残余缺口；不能因此通过“穷尽系统综述”门禁。G3 通过只表示该版内容审核完成，不等于期刊接收或最终投稿就绪。

## 12. 责任、复核和问题处理

负责人裁决纳入范围、重要争议、正文关键判断和发布。A/B/C 负责各主题提取，交叉复核原则为 A 查 B、B 查 C、C 查 A；工作量不均时由负责人调整。

直接进入正文的关键结论、数字、分类争议和版本冲突全部复核。其他目录元数据可分层抽查；每批登记抽样范围、实际数量与问题，抽查比例不解释为统计可靠性证明。

机器/AI 可以发现候选、匹配标识符、提示疑点和起草，不能自行把“候选”改成“已复核”。同一助手的自检不登记为第二位独立复核者；没有人类交叉复核时保留相应待办。

| 问题等级（不是论文证据等级） | 示例 | 处理 |
|---|---|---|
| 阻断 | 错配论文、伪造状态/数字、结论无原文支撑、泄露访问凭据、身份冲突 | 停止使用受影响记录或判断；修复或撤除后再过门禁 |
| 重要 | 版本不一致、控制收益误归因、跨协议比较、核心方向未检查 | 修复、收窄论述或明确残余缺口；负责人确认处置后才能交付 |
| 一般 | 非关键字段欠完整、样式、拼写、非结论性链接展示 | 登记修复；不以一般问题掩盖阻断问题 |

问题记录最小格式：编号、影响记录/小节、问题、原文依据、处理决定、负责人、复核人、状态。修正记录保存前值、后值、依据和日期；争议不能靠覆盖旧单元格消失。

每周或每批汇报四件事：本批实际核验了什么；改变了哪些分类/判断；还缺什么；需要谁作决定。论文数量只作为辅助计数，不作为同学排名或奖励依据。

## 13. 同步、验证与公开边界

先审核主表/决定与证据，再生成七类目录、BibTeX 与 PDF；检查 diff 后发布。正文、目录和统计使用同一批次快照，不要求目录每一篇都被正文引用。

现有论文族一致性检查可复用：`python literature/build_publication_families.py --check`。它仅检查生成产物与决定的一致性，不能证明全部身份真实或召回充分。

后续按需增加最小检查：稳定编号不重复、引用 key 均存在、标识符冲突报警、各层计数一致、公开链接不含访问凭据、PDF 与当前源码对应。身份核验和结论复核仍需要原始来源与人工判断。

不另起复杂系统，不在本轮实现检查程序、网站或自动定时任务。规则之外的执行工具须等后续授权后，优先复用已有脚本。

GitHub 首页保留项目简介、论文入口、四部分框架、七类导航与贡献入口；内部问题日志、私有路径、学生信息和访问凭据不进入首页。图表或 PDF 公开更新须检查授权、版权、匿名要求及披露信息。

匿名作者占位不是真实署名信息。最终投稿前另核作者贡献、版权/图片权限、ACM 当时适用的格式与 AI 披露要求，不在本规则中声称已满足投稿要求。
